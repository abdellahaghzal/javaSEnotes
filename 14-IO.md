# Chapter 14: I/O

## Files and the File Class
- Constructors: `new File(String path)`, `new File(String parent, String child)`, and `new File(File parent, String child)`. There is no three-argument constructor and no `File(String, File)` constructor.
- Creating a `File` object never throws an exception and does not create anything on disk, even if the path does not exist.
- Common methods: `exists()`, `isFile()`, `isDirectory()`, `getName()`, `getPath()`, `getAbsolutePath()`, `length()`, `listFiles()`, `mkdir()`, `mkdirs()`, `renameTo()`, `delete()`.
- `delete()` returns a `boolean` (`false` if it failed or the file doesn't exist). It does not throw an exception for a missing file.
- A path starting with the root (such as `/home/parrot`) is an **absolute** path. A path that does not is **relative** to the working directory. A path alone does not say whether it is a file or a directory.
- Convert between the two APIs with `file.toPath()` and `path.toFile()`.
- `new File("weather", "/winter/snow.dat")` treats `weather` as relative to the working directory, so it does not point to `/weather/winter/snow.dat`.

## Path Symbols (Table 14.1)
- `.` — A reference to the current directory
- `..` — A reference to the parent of the current directory

## Creating and Using Path
- Create a `Path` with `Path.of(String first, String... more)` or `Paths.get(...)`, or with `file.toPath()`. There is no `new Path()` constructor and no `Path.get()` method.
- `Path` is immutable. Methods such as `normalize()`, `resolve()`, and `relativize()` return a **new** `Path` and never change the original. If the return value is ignored, the original is printed unchanged.
- `getNameCount()`, `getName(int)`, `subpath(begin, end)` (end exclusive), `getFileName()`, `getParent()`, `getRoot()`, `isAbsolute()`, `toAbsolutePath()`, `startsWith()`, `endsWith()`.
- Name indexes do not count the root. For `/zoo/animals/bear/koala/food.txt`, index 0 is `zoo`, `subpath(1, 3)` is `animals/bear`, and `subpath(1, 3).getName(1)` is `bear`.
- `normalize()` removes `.` and resolves `..` symbols (only textually; it does not check the file system).
- `resolve(other)` appends `other` to the path. If `other` is an **absolute** path, `resolve()` returns `other` unchanged (for example `Path.of("./dog.txt").resolve(Path.of("/pets/../cat.txt"))` is `/pets/../cat.txt`).
- `relativize(other)` builds the path from one to the other. Both paths must be absolute or both relative, or an exception is thrown.
- `toRealPath()` returns the real, normalized path (following symbolic links) and throws `IOException`. The file must exist.
- `path.equals(other)` compares the path values only, so `/lizard/./walking.txt` and `/lizard/././actions/../walking.txt` are **not** equal.
- `Files.isSameFile(a, b)` first checks `equals()`, and if that is false, checks whether both refer to the same file in the file system. It throws an exception if the files do not exist.
- `Files.mismatch(a, b)` returns `-1` if the contents are identical, or the position of the first difference.

## Common Causes of Methods Throwing IOException
- Loss of communication to the underlying file system
- File or directory exists but cannot be accessed or modified
- File exists but cannot be overwritten
- File or directory is required but does not exist
- Most `Files` methods (`createDirectory()`, `deleteIfExists()`, `readAllLines()`, `copy()`, `move()`, `walk()`) throw the checked `IOException`, so the calling method must handle or declare it.

## The Files Helper Class
- Check methods: `exists()`, `isDirectory()`, `isRegularFile()`, `isSymbolicLink()`, `isHidden()`, `size()`.
- `Files.createDirectory(path)` creates one directory and fails if the parent does not exist. `Files.createDirectories(path)` creates all missing parents and returns the `Path`. There is no `Files.mkdir()`.
- `Files.delete(path)` throws an exception if the path doesn't exist. `Files.deleteIfExists(path)` returns `true` if it deleted the path and `false` if nothing was there. A directory must be empty to be deleted.
- `Files.copy(source, target, options)` copies a file. The `target` must be the **full destination path**, not just the directory. If the target already exists, it throws `FileAlreadyExistsException` unless `REPLACE_EXISTING` is passed. A directory copy does not copy its contents.
- `Files.move(source, target, options)` moves or renames a file. `ATOMIC_MOVE` makes the move happen as one file system operation, so no other process sees a partially moved file. It does not mean the target directory is used as a destination folder, and what happens to an existing target is implementation-specific.
- `Files.readAllLines(path)` returns a `List<String>`, not a stream, so `flatMap()`, `map()`, and `filter()` cannot be chained on it directly. Use `Files.lines(path)` to get a `Stream<String>`.
- `Files.readString()` and `Files.writeString()` read and write whole files. `Files.newBufferedReader()` and `Files.newBufferedWriter()` return buffered character streams.
- NIO.2 has no single method to delete an entire directory tree. You can use `Files.walk()` or `Files.walkFileTree()` to build one yourself.

## Traversing Directories
- `Files.list(path)` — streams the entries of one directory only (not recursive).
- `Files.walk(path)` / `Files.walk(path, maxDepth)` — streams a whole directory tree (depth-first). Its stream is `Stream<Path>`, so `filter()` takes a one-argument `Predicate<Path>`.
- `Files.find(path, maxDepth, BiPredicate<Path, BasicFileAttributes>, options)` — like `walk()`, but the filter takes two arguments, the path and its attributes. The `maxDepth` is required.
- A `maxDepth` of `0` means only the starting path itself. For `find(f, 0, ...)` the stream contains at most `/monkeys` itself, so a filter that keeps only symbolic links finds nothing if the starting path is not a link.
- By default, `walk()` and `find()` do **not** follow symbolic links. Pass `FileVisitOption.FOLLOW_LINKS` to follow them, which can lead to a `FileSystemLoopException` on circular links.
- These stream methods hold open resources, so use try-with-resources to close the `Stream`.
- Walking a file system from the root visits everything the user can read, so an unreadable directory can result in a runtime exception (for example, `UncheckedIOException` wrapping `AccessDeniedException`).
- Calling `Files.walk(x.toRealPath().getParent())` on `/animals/fluffy/..` resolves to `/animals`, and its parent is the root `/`.

## Symbolic Links
- Many `Files` methods follow symbolic links by default. Pass `LinkOption.NOFOLLOW_LINKS` to avoid following them.
- If `/kang` is a symbolic link to `/mammal/kangaroo`, creating `/kang/joey` creates the directory inside `/mammal/kangaroo`, so it is reachable at both `/kang/joey` and `/mammal/kangaroo/joey`. It may fail if that directory already exists.

## Common NIO.2 Method Arguments (Table 14.4)
- **LinkOption.NOFOLLOW_LINKS** — Do not follow symbolic links
- **StandardCopyOption.ATOMIC_MOVE** — Move file as atomic file system operation
- **StandardCopyOption.COPY_ATTRIBUTES** — Copy existing attributes to new file
- **StandardCopyOption.REPLACE_EXISTING** — Overwrite file if it already exists
- **StandardOpenOption.APPEND** — If file is already open for write, append to the end
- **StandardOpenOption.CREATE** — Create new file if it does not exist
- **StandardOpenOption.CREATE_NEW** — Create new file only if it does not exist; fail otherwise
- **StandardOpenOption.READ** — Open for read access
- **StandardOpenOption.TRUNCATE_EXISTING** — If file is already open for write, erase file and append to beginning
- **StandardOpenOption.WRITE** — Open for write access
- **FileVisitOption.FOLLOW_LINKS** — Follow symbolic links

## File Attributes
- `Files.readAttributes(path, BasicFileAttributes.class)` reads many attributes in a single call and returns a read-only snapshot. It is often more efficient than calling `Files.size()`, `Files.isDirectory()`, and so on separately.
- `BasicFileAttributes` provides `size()`, `isDirectory()`, `isRegularFile()`, `isSymbolicLink()`, `creationTime()`, `lastModifiedTime()`, and `lastAccessTime()`. It has no setter methods, so `a.setTimes(...)` does not compile.
- To **modify** attributes, use an updatable view: `Files.getFileAttributeView(path, BasicFileAttributeView.class)`, whose `setTimes(lastModified, lastAccess, create)` can change the times.
- Operating system–specific attributes are available through types such as `PosixFileAttributes` and `DosFileAttributes`, or with a view-name string such as `"posix:permissions"`.
- `Files.readAttributes()` works with a `Path`, not a `File` object.

## Differences Between Byte and Character I/O Streams
- Byte I/O streams read/write binary data (0s and 1s) and have class names that end in `InputStream` or `OutputStream`
- Character I/O streams read/write text data and have class names that end in `Reader` or `Writer`
- A `Reader` or `Writer` handles character encoding, which makes it the better choice for text (`String`) data. It does not provide multithreading support.
- Reading binary data into a Java object is done with `ObjectInputStream`. Writing is done with `ObjectOutputStream`. There are no `ObjectReader` or `ObjectWriter` classes.

## Common I/O Stream Classes
- **Low-level streams** (work directly with a file or network resource): `FileInputStream`, `FileOutputStream`, `FileReader`, `FileWriter`.
- **High-level streams** (wrap another stream): `BufferedInputStream`, `BufferedOutputStream`, `BufferedReader`, `BufferedWriter`, `ObjectInputStream`, `ObjectOutputStream`, `InputStreamReader`, `OutputStreamWriter`, `PrintStream`, `PrintWriter`.
- A byte stream wraps a byte stream, and a character stream wraps a character stream. `new BufferedInputStream(new FileInputStream("z.txt"))` is valid and can be passed to another `InputStream` wrapper such as `BufferedInputStream` or `ObjectInputStream`. `BufferedReader` and `BufferedWriter` take a `Reader`/`Writer`, not an `InputStream`. `InputStreamReader` bridges a byte stream to a character stream.
- `FileInputStream` takes a `File` or `String` path, not another `InputStream`.
- The best choice for reading text from a large file is `BufferedReader` wrapped around `FileReader`. There are no `PrintInputStream` or `PrintReader` classes.
- Useful methods: `read()` (one value, `-1` at the end), `read(char[])` / `read(byte[])` (returns the number read, or `-1`), `write()`, `flush()`, `close()`, `BufferedReader.readLine()`, `BufferedWriter.newLine()`.
- A `read(buffer)` call only replaces the characters it read. Writing the whole buffer again can write leftover characters from the previous read. For example, with a 5-char buffer and file `ABCDEF`, the reads give `ABCDE` and then `F` (the buffer is `FBCDE`), so copying with `writer.write(buffer)` yields `ABCDEFBCDE`.
- A writer may hold data in a buffer until `flush()` or `close()`, so a file can look empty or incomplete while the program is running.
- Closing a high-level stream closes the stream it wraps. A stream that is created but never closed (such as a reader declared outside the try-with-resources) is a resource leak.
- `mark(int)`, `reset()`, and `skip(long)` are optional. `skip(n)` may skip **fewer** than `n` characters, so results using it can vary. `reset()` goes back to the marked position.
- A variable can be used in try-with-resources if it is effectively final: `try (var f = ...; o)`. After the try block, that resource is closed, so using it again (for example `o.write("")`) throws an `IOException` (`Stream closed`).

## Console and System Streams
- `System.console()` returns a `Console`, or **`null`** if the program is not running from an interactive console. Using it without a null check can throw a `NullPointerException`.
- `Console` methods: `readLine()`, `readPassword()`, `format()`, `printf()`, `reader()`, `writer()`, `flush()`.
- `console.writer()` returns a `PrintWriter`, but declaring it as a `Writer` means `append()`, `flush()`, and `close()` throw the checked `IOException`.
- The system streams are `System.in`, `System.out`, and `System.err`.

## How to Make a Class Serializable
- The class must be marked `Serializable`
- Every instance member of the class must be serializable, marked `transient`, or have a null value at the time of serialization
- `Serializable` is a marker interface (no methods), not a functional interface. The class implements it. It does not extend it, and it does not have to declare a `serialVersionUID` (that is optional).
- A record is **not** automatically serializable. It must implement `Serializable` like any other class.
- Write with `ObjectOutputStream.writeObject()`. Read with `ObjectInputStream.readObject()`, which throws `ClassNotFoundException` and needs a cast.
- A non-null, non-transient instance member that is not serializable (such as a plain `Object`) compiles, but throws a `NotSerializableException` at runtime. An empty `ArrayList` is serializable.
- `transient` instance variables come back as their default value (`null`, `0`, `false`) after deserialization.
- `static` variables are not part of the serialized object.
- On deserialization, the constructor and instance initializers of the serializable class are **not** run, so a value set there is lost (a `transient` field set in a constructor ends up `null`).
- If a serializable class extends a class that is **not** serializable, the parent's no-argument constructor runs during deserialization, so the parent's fields get the values set in that constructor (for example `name = "Matt"`).
- Serialization turns Java objects into data. It does not turn data into objects (that is deserialization).

## Selecting a Search Strategy (Directory Traversal)
- **Depth-first search** — traverses the structure from the root to an arbitrary leaf and then navigates back up toward the root, traversing fully any paths it skipped along the way
- **Breadth-first search** — starts at the root and processes all elements of each particular depth before proceeding to the next depth level
- `Files.walk()` uses depth-first search.

## Exam Essentials
- **Understand files and directories.** Files are records that store data within a persistent storage device, such as a hard disk drive, that is available after the application has finished executing. Files are organized within a file system in directories, which in turn may contain other directories. The root directory is the topmost directory in a file system.
- **Be able to use File and Path.** An I/O File instance is created by calling the constructor. It contains a number of instance methods for creating and manipulating a file or directory. An NIO.2 Path instance is an immutable object that is created from the factory method `Path.of()`. The Path interface includes many instance methods for reading and manipulating the path value. Know how `normalize()`, `resolve()`, `relativize()`, and `subpath()` work, and that they return new `Path` objects.
- **Distinguish between types of I/O streams.** I/O streams are categorized by byte/character, input/output, and low-level/high-level. Byte streams operate on binary data and have names that end with Stream, while character streams operate on text data and have names that end in Reader or Writer. The InputStream and Reader classes are the topmost abstract classes that receive data, while the OutputStream and Writer classes are the topmost abstract classes that send data. A low-level stream is one that operates directly on the underlying resource, such as a file or network connection. A high-level stream operates on a low-level or other high-level stream to filter data, convert data, or improve performance.
- **Understand how to use Java serialization.** A class is considered serializable if it implements the `java.io.Serializable` interface and contains instance members that are either serializable or marked transient. All Java primitives and the String class are serializable. The ObjectInputStream and ObjectOutputStream classes can be used to read and write a Serializable object from and to an I/O stream, respectively. Know what happens to transient fields, static fields, and constructors when an object is deserialized.
- **Be able to interact with the user.** Be able to interact with the user using the system streams (System.out, System.err, and System.in) as well as the Console class. The Console class includes special methods for formatting data and retrieving complex input such as passwords. `System.console()` can return `null`.
- **Manage file attributes.** The NIO.2 Files class includes many methods for reading single file attributes, such as its size or whether it is a directory, a symbolic link, hidden, etc. NIO.2 also supports reading all of the attributes in a single call. An attribute type is used to support operating system–specific views. Finally, NIO.2 supports updatable views for modifying selected attributes.
- **Watch for compile errors first.** Common traps: a method that throws `IOException` that is not handled, `flatMap()` called on a `List`, a two-argument lambda passed to `Files.walk().filter()`, `Files.mkdir()` or `new Path()` (which do not exist), and `setTimes()` called on `BasicFileAttributes`.
